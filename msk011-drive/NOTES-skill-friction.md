# Skill/template friction

- `dsp/src/netlist.rs:21-32` explicitly excludes BJT leakage and charge storage; `dsp/src/circuit.rs:20-30,71-72,144-165` omits ISE/NE and junction charges. The published Fairchild/onsemi 2N5088 model contains both. `SKILL.md` describes BJTs as Gummel–Poon without mentioning leakage is absent. Proposed upstream fix: disclose the exact supported parameter subset in the skill and model documentation; add an explicit model-compatibility check; implement and test leakage and nonlinear junction/transit charge before claiming equivalence with full published BJT models.
- `SKILL.md` step 3 calls for a plausible operating point with all transistors forward-active and output at 0 V. A driven or strongly asymmetric circuit can intentionally bias some devices outside forward-active; AC-coupled output zero does not by itself validate internal bias. Proposed fix: compare the complete bias state against the sourced design and identify any justified exceptions instead of treating those as universal rules.
- `references/method.md:8` says both descriptions use the same device models, but current BJT support drops leakage and charge storage. Proposed fix: distinguish an exact SPICE match from a deliberately reduced model and require explicit disclosure and independent full-model-vs-reduced-model checks.
- `validate.sh:21,23-38` caches the signal pack merely by presence and SPICE reference keyed by netlist hash and controls; it does not include pack configuration/content, simulator version, or SPICE runner code in the cache key. Switching QUICK and full runs can reuse a quick pack, invalidating a purported full validation. Proposed fix: key the pack and references by signal generation arguments and content hashes, runner version and relevant simulation settings, or regenerate automatically on mismatch.
- `SKILL.md` prerequisites insist ngspice >=47 and recommend Homebrew, but in this environment ngspice 45 from nix successfully ran the template validation according to the supplied setup. Proposed fix: describe 47 as a performance recommendation and document Nix installation; do not treat earlier compatible versions as intrinsically unusable.
- At Level=0.05, the block Gauss–Seidel inter-device sweep stopping criterion of 1e-7 V produced artificial third/fifth harmonics at approximately -79 dBc for a -40 dBFS/5 kHz input; SPICE placed them below -120 dBc. Tightening only `sweep_error()` to 1e-12 V removed the artifact without loosening any comparison tolerance. Tightening the single-device or joint Newton thresholds alone had no effect. This substantially increases CPU and should be addressed by a more efficient solver and a regression test upstream.
