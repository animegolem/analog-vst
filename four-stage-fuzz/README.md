# Four Stage Sustainer

A four-transistor distortion plugin modeled after the American V3 Big Muff Pi circuit in ElectroSmash's analysis, not other versions. Trademarks belong to their respective owners. No schematic or graphics are redistributed here.

## Source and scope

- ElectroSmash, **Big Muff Pi Analysis**, V3 complete labeled circuit diagram and parts discussion, archived from 2022: https://electrosmash.mas-effects.com/big-muff-pi-analysis.html . The diagram is authoritative where its article text conflicts with it (including R11 10k and R6 15k; R7 is 430k). Every value and node is transcribed explicitly in `reference/circuit.cir`; see its header.
- Q1–Q4 use the reduced 2N5088 model cited by the sibling MSK-011 project, from Fairchild/onsemi https://www.onsemi.com/pdf/datasheet/2n5088-d.pdf . The source analysis explicitly lists 2N5088 as a BC239 substitute. The model retains IS, BF, BR, VAF, IKF, RB, RC, RE; RE defaults to zero. Junction charge storage and leakage are omitted in **both** implementations. That is a substantive approximation: actual junction capacitances, Miller effect, charge storage and low-current beta can change frequency response, dynamics and distortion. The vendor's zero-bias CJC is 4.017 pF versus each explicit 470 pF feedback capacitor (about 0.85% before bias dependence); CJE is 4.973 pF. This simple comparison is not an error or audibility measurement: junction charge, saturation and the uncompensated recovery stage can matter differently. No quantitative estimate of audibility or hardware error has been measured.
- The 1N914 pairs use the template's 1N4148 equivalent; the fixed diode capacitance approximation differs from SPICE's voltage-dependent capacitance. No hardware calibration is claimed.
- Ideal 9 V supply; input source impedance 1k, output load 1M; full-scale input corresponds to 0.2 V peak, typical guitar level. Bypass switch, LED, supply decoupling, noise and component tolerances omitted. Pot minimum resistance is clamped to 1 ohm. Knobs are 100k linear; clockwise tone increases the high-pass branch.
- Tests validate this **reduced model against the matching SPICE model**, not against a physical pedal or full transistor models. A full validation passes at all 7 settings, including volume at 0 (2026-11-17). Validation renders each test section from a fresh DC state, as SPICE does; `diagnostics/state-mismatch.md` records why.

## CPU warning

Measured 337% of one core for one stereo instance at 48 kHz (2026-11-17, circuit rate 672 kHz, one benchmark at a time). The plugin is for offline bounce or freeze only.

The complete coupled nonlinear circuit has an exceptionally high CPU cost. At the first benchmark it used approximately 1028% of one core for one stereo instance at 48 kHz while other work was running; this measurement is not a real-time-performance guarantee and is likely too costly for practical live use.

## Shared Solver (carried in 2026-11-19; Full Validation pending)

`dsp/src/circuit.rs`, `netlist.rs`, `processor.rs` and `render/src/main.rs` are now the same files in all eight Projects; `tools/check-shared.py` at the repository root fails when a copy drifts. This Circuit takes the joint Newton solve, which changes here: each junction's step is limited as SPICE does, the bound is 200 iterations instead of 64, and a sample that does not converge is held, counted and refused by `render` where the earlier Solver committed it. Also new: the DC operating point check and rest-state pin, a return to the construction-time operating point after 1024 held samples in a row, and rejection of non-finite input and NaN Control values. The first carry was compared by rendering six short inputs (silence, 1 kHz at -12 and 0 dBFS, 5 kHz at 0 dBFS, 200 Hz at +12 dBFS, a 0 dBFS sweep) at every Setting through the `render` of the commit before the carry and through the new one: no sample was held, and with the pin removed all 42 renders are bit-identical, so on these inputs the new solve takes the same steps as the old one. With the pin the largest difference is -86.3 dBFS, in silence at `sustain_max`: the earlier Solver's silent render had a start-up transient of -86.3 dBFS there (-110.1 dBFS at the default Setting) and the new one stays under -380 dBFS at every Setting. With signal the largest difference is -89.6 dBFS (200 Hz at +12 dBFS, `sustain_max`). The operating point moves by 1.318 V with Tone, and the rest state is solved once, at construction. A return to rest after Tone has moved restores the old state, the circuit settles to within 10 microvolts of the present operating point in 4 s with no further held sample, and the output transient is the same as for the Tone change itself: 1.2 V toward Tone 0 and 2.0 V toward Tone 1, against 0.2 V at 0 dBFS (unit test, forced; no input tried reaches it). The validation figures in this README were measured with the earlier Solver. **No Full Validation has been run with the shared Solver.**

**Second pass, 2026-11-19.** The Netlist's transistors have RE = 0, which `Netlist` used to enter as a 1 milliohm resistor behind an internal node; it now adds no resistor, as ngspice does. The Circuit matrix has four nodes fewer; the solve path and the device order are unchanged. `render` now also refuses a capture that contains a sample that is not finite, and when it refuses a capture it removes a file already at the output path (never the input). `render/tests/refused_capture.rs` is a fifth shared file and runs the built binary on a sine at the largest 32-bit float value with every Control at 1; this Model refuses it through held samples (2423). The ignored DC bounds test now builds the Model at 4096 seeded Control positions (not five values per Control) at the four base rates; worst over all of them: last Newton step 2.17e-11 (4615 times under the bound; the first carry's five-value grid measured 3.24e-9 with the 1 milliohm stand-in), relative DC residual 5.54e-15 (180 times), pin distance 4.9e-11 V. Compared again with the `render` of the commit before the carry on five short inputs (silence, 1 kHz at -12 dBFS, 5 kHz at 0 dBFS, 440 Hz with 5.5 kHz at 0 dBFS peak, a 2 kHz burst at -3 dBFS between silences; 48 kHz mono) at all seven Settings: the largest difference is still the -86.3 dBFS start-up transient the earlier Solver had in silence at `sustain_max`, which the pin removes. The terminal-resistance change accounts for -95.0 dBFS (`tone_max`, the two-tone input, on a +13.3 dBFS peak); with it and the pin removed the 35 renders are bit-identical to the earlier Solver's. No sample was held. Cost, bench run from the commit before the carry and from this Solver back to back, three times each in turn, one-minute load average 5 to 8: 330.7, 331.5, 336.4 before, 350.2, 353.0, 357.2 after (% of one core per stereo instance at 48 kHz). Not run with this Solver: `./validate.sh` in any mode and `./install.sh`. **No Full Validation has been run with the shared Solver.**
