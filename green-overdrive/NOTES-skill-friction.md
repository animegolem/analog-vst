# Skill and template friction

- `validate.sh:21`: QUICK and full validation share `validation/pack/pack.json`; a quick pack created first is silently reused by a later full run. Put quick and full packs in separate directories or record pack type/hash in a manifest and regenerate on mismatch. The final full run here started from an empty pack.
- `validate.sh:23-35`: reference cache key includes netlist and controls, but not test pack, simulator version, harness code or sampling settings. Include content hashes of pack manifest/WAV and simulation implementation/version to avoid stale captures.
- `validate.sh:14-17` and skill prerequisites mandate ngspice >=47 yet a nix-provided 45 has the XSPICE code model and runs the template; detect capability, not just version, and document that older versions may be fast enough.
- `harness/src/analog_harness/spice.py:131-156`: default fan-out uses all detected CPUs with 45 full sections, per-section 900s timeout, and there is no per-setting estimated runtime; document `HARNESS_JOBS`, progress, expected memory and timeout behavior for nonlinear circuits.
- `dsp/src/netlist.rs:21-32,172-202`: BJT is a restricted Gummel-Poon subset, not a full published SPICE model; NF, NE, ISE, junction capacitances and transit time have no representation. List supported parameters explicitly in the skill and warn that simplifying a device changes its physical behavior even when the two simulations match.
- `dsp/src/control.rs:21-24`: only linear, log, and two-segment audio tapers exist; the published circuit describes a G/W tone taper. Add a measured/custom taper helper or explicitly document the linear approximation.
- `reference/circuit.cir:19` template diode has nonlinear charge storage in ngspice while Rust treats junction capacitance as a fixed Cjo and omits TT; explain the mismatch prominently in method.md, not only as a pitfall.
- `harness/src/analog_harness/spice.py:94-113`: ngspice 45 can fail both gmin and source stepping for the max-drive circuit, then silently succeed with `Transient op` and a false initial output voltage; the return code is zero. This project raises only the iteration limits (not accuracy tolerances) and rejects that fallback. Upstream should check the initial operating point and stderr explicitly and test high-feedback circuits.
- `dsp/src/circuit.rs:367-469,609-662`: at zero level, a 3 s silence test produced a steady ~-0.97 micro full-scale output even though the AC-coupled SPICE output settles to zero. Tightening the Newton and sweep thresholds and eliminating a mathematically redundant supply capacitor did not remove it; investigate MNA conditioning/state cancellation and add a silence/DC regression test at attenuator endpoints.
- `harness/src/analog_harness/spice.py:131-156`: the independent sections begin at DC while the renderer runs continuously and only 0.5 s of silence separates sections. With long bias/coupling time constants and a nearly muted direct path this is not necessarily equivalent. Evidence: the level=0, 1 kHz/-40 dBFS step reports 0.273 dB gain error in the continuous pack; starting the DSP from rest for the identical isolated step gives -80.82952 dB gain vs -80.82958 dB SPICE. The isolated burst still nulls only -30.34 dB (DC residual; mean-removed -63.3 dB), so section memory is not the only issue. Increase quiet settling as required by circuit poles or compare identical initial conditions, and add a regression test.
- `dsp/examples/bench.rs:11-23`: wall-clock CPU measurement is heavily affected by competing validation jobs; document that it must run when the system is idle and preferably report repeated trials.
